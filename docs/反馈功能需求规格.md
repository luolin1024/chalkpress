# chalkpress 反馈功能需求规格（给 omp）

## 目标

在 chalkpress 应用内增加「用户反馈」功能：用户在 GUI 里提交反馈（类型/内容/联系方式），反馈数据通过**飞书自定义机器人 webhook** 推送到用户的飞书群，群内配合**飞书多维表格**归档管理。

## 功能需求

### 1. 入口与 UI
- 位置：GUI 侧栏设置区新增「反馈」入口（或标题栏 ❓ 图标 → 下拉菜单含「问题反馈」）
- 弹窗表单字段：
  - 反馈类型（必选，segmented）：bug 报告 / 功能建议 / 使用问题 / 其他
  - 内容描述（textarea，必填，10-500 字）
  - 联系方式（选填，文本，如邮箱/微信，用户自愿）
  - 可选勾选：「附带诊断日志」（勾选后附 logs_dir() 最近一份运行日志；默认不勾，明确提示日志可能含文件路径）
- 提交按钮 → 状态反馈（提交中/成功/失败+重试）

### 2. 数据收集（反馈 payload）
```json
{
  "type": "bug|suggestion|question|other",
  "content": "用户输入",
  "contact": "选填",
  "app_version": "从 update.py 的版本常量取",
  "os": "platform.platform() 摘要（macOS 15.x / Windows 11 ...）",
  "attach_log": true/false,
  "log_excerpt": "日志末尾 50 行（仅勾选时）",
  "ts": "ISO8601"
}
```

### 3. 传输：飞书自定义机器人 webhook
- 配置方式：**环境变量/打包时注入**，不让用户配置（反馈直达开发者自己的群）
  - `CHALKPRESS_FEEDBACK_WEBHOOK`（编译期通过 PyInstaller spec 或 .env 打入；运行时读取，未设置则整个反馈入口隐藏/禁用并 log）
- POST JSON 到 webhook，使用 **msg_type=text**（最简单可靠，群机器人无卡片权限要求）：
```json
{"msg_type": "text", "content": {"text": "📋 [chalkpress反馈] 类型: bug\n内容: xxx\n版本: v0.5.0\nOS: macOS\n联系方式: xxx\n---\n日志已附（如勾选）"}}
```
- 日志 excerpt 太长时（>2000 字）截断，或者拆第二条消息
- **超时与重试**：10s 超时，失败重试 2 次；仍失败 → 显示「提交失败，请通过 GitHub Issues 反馈」+ 附 issues 链接按钮
- **隐私红线**：webhook 请求里绝不含用户视频内容/转写文本（只有用户主动填写的反馈字段+日志 excerpt）

### 4. 飞书多维表格归档（最终方案：方案 B 变体——直连飞书开放 API）

**已定方案（用户 2026-11-05 确认）**：不走群机器人 webhook，直接用**飞书自建应用机器人**调开放 API 写多维表格。

- **应用凭据（用户提供，部署时写入本地 env，不入仓库）**：
  - App ID: `cli_aa61c20847389c03`
  - App Secret: 见本地 `~/.config/chalkpress-feedback.env`（600 权限）——**禁止写入任何仓库文件**
- **归档目标**：飞书多维表格（bitable）——需用户提供 app_token/table_id（或由应用首次运行时引导创建）
- **实现路径**：
  1. `feedback.py`: tenant_access_token 获取（POST /open-apis/auth/v3/tenant_access_token/internal，app_id+secret）→ 缓存 2 小时
  2. 写入 bitable：POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records（字段：类型/内容/联系方式/版本/OS/日志摘要/时间）
  3. 失败降级：API 失败重试 2 次 → 仍失败显示 GitHub Issues 引导
- **安全优势**：App Secret 不进客户端二进制！
  - ⚠️ 但注意：客户端直连飞书 API 需要 secret——**桌面应用里放 secret 仍可被逆向**
  - **修正方案**：app 内反馈先 POST 到用户 ECS 上的轻量端点（复用 lead-server 模式，ECS 持有 secret 调飞书 API）→ ECS 写 bitable
  - 若用户接受「客户端直连+secret 打包」的风险（反馈量小、监控异常），也可先行，secret 用 KMS/混淆保护
- **表格字段设计**：反馈类型(单选)/内容(文本)/联系方式(文本)/应用版本(文本)/操作系统(文本)/日志摘要(文本)/提交时间(日期)
- **EPS 备忘**：pptcopilot-ecs 已有 lead-server（Flask + 飞书 bot）同模式可复制

### 5. 代码落点（遵循 chalkpress AGENTS.md 约定）
- 新模块 `chalkpress/feedback.py`：`submit_feedback(payload) -> bool`（requests 直 POST，10s 超时，重试 2 次；webhook 未配置返回 False）
- GUI：gui.py 设置 pane 或菜单加反馈入口 + tkinter 简单表单弹窗（与现有 GUI 风格一致，tkinter messagebox/Toplevel）
- 版本号：`update.py` 里已有版本常量，直接引用
- 日志：用户勾选时读 logs_dir() 最新文件尾部 50 行
- 配置：`config.py` 加 `FEEDBACK_WEBHOOK` 读取链（env > config.toml > None）
- 打包：PyInstaller spec 无需改（纯 Python requests）；CI 不含 webhook secret（本地打包时注入 env）

### 6. 验收标准
- [ ] GUI 有反馈入口，表单四字段完整
- [ ] 提交成功 → 飞书群收到消息（用户肉眼确认）
- [ ] 不勾选日志时 payload 不含任何日志内容
- [ ] webhook 未配置时入口隐藏，应用正常使用无报错
- [ ] 提交失败有 GitHub Issues 降级引导
- [ ] `pnpm build`/PyInstaller 打包通过，全部现有功能不受影响
